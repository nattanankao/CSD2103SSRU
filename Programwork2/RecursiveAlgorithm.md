## 1. จำนวนครั้งที่แต่ละอัลกอริทึมประมวลผลตัวอักษร

### Recursive
Recursive จะเรียกเมธอดซ้ำตามจำนวนตัวอักษรในสตริง เช่น ถ้าสตริงยาว 100 ตัว ก็จะเรียกเมธอดประมาณ 100 ครั้ง แต่ในแต่ละรอบจะมีการสร้าง String ใหม่ ทำให้มีการคัดลอกข้อมูลหลายครั้ง จึงใช้เวลามากขึ้นเมื่อข้อมูลมีขนาดใหญ่

### Iterative
Iterative ใช้ลูปวนจากตัวอักษรตัวสุดท้ายมาถึงตัวแรก อ่านข้อมูลทั้งหมดเพียงครั้งเดียวตามจำนวนตัวอักษร และใช้ `StringBuilder` เก็บผลลัพธ์ จึงทำงานได้เร็วกว่า

## 2. Time Complexity

- Recursive : **O(n²)**
- Iterative : **O(n)**

Recursive ใช้เวลามากกว่า เพราะนอกจากจะเรียกเมธอดหลายครั้งแล้ว ยังมีการสร้าง String ใหม่ทุกครั้ง ส่วน Iterative ใช้ลูปเพียงครั้งเดียว จึงมีประสิทธิภาพดีกว่า

## 3. Space Complexity

- Recursive : **O(n)**
- Iterative : **O(n)**

Recursive ใช้พื้นที่สำหรับ Call Stack และ String ที่สร้างขึ้นระหว่างการทำงาน ส่วน Iterative ใช้พื้นที่ของ `StringBuilder` ในการเก็บผลลัพธ์

## 4. ผลกระทบจากการต่อสตริงด้วยเครื่องหมาย `+`

การใช้ `+` กับ `String` จะทำให้ Java สร้าง String ใหม่ทุกครั้งที่ต่อข้อความ ทำให้ต้องคัดลอกข้อมูลเดิมซ้ำ ๆ หากข้อมูลมีขนาดใหญ่จะทำให้โปรแกรมทำงานช้าลงและใช้หน่วยความจำมากขึ้น

## 5. ความแตกต่างระหว่าง String และ StringBuilder

`String` ไม่สามารถแก้ไขข้อมูลเดิมได้ เมื่อมีการต่อข้อความจะสร้าง Object ใหม่ทุกครั้ง

`StringBuilder` สามารถเพิ่มข้อความใน Object เดิมได้ จึงใช้หน่วยความจำน้อยกว่า และเหมาะกับงานที่ต้องต่อข้อความหลายครั้ง

## 6. ผลการทดสอบ

จากการทดลองพบว่า

| ขนาดสตริง | Recursive | Iterative |
|------------|-----------|-----------|
| 10 ตัวอักษร | ทำงานได้ปกติ | ทำงานได้ปกติ |
| 100 ตัวอักษร | เริ่มช้าลงเล็กน้อย | ทำงานได้ปกติ |
| 1,000 ตัวอักษร | ใช้เวลามากขึ้นอย่างเห็นได้ชัด | ยังทำงานได้รวดเร็ว |
| 10,000 ตัวอักษร | ใช้เวลานาน และมีโอกาสเกิด StackOverflowError | ยังทำงานได้ปกติ |
