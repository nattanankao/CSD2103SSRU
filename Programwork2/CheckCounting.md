## 1. Time Complexity

- Recursive Counting : **O(n)**
- Iterative Counting : **O(n)**

ทั้งสองวิธีต้องตรวจสอบตัวอักษรทุกตัวในสตริงอย่างน้อยหนึ่งครั้ง จึงมี Time Complexity เท่ากันคือ O(n)

## 2. Space Complexity

- Recursive Counting : **O(n)**
- Iterative Counting : **O(1)**

Recursive ใช้พื้นที่ของ Call Stack จากการเรียกเมธอดแบบเวียนเกิดตามจำนวนตัวอักษร ส่วน Iterative ใช้เพียงตัวแปรสำหรับนับจำนวนสระและพยัญชนะ จึงใช้พื้นที่คงที่

## 3. จำนวน Recursive Calls

Recursive จะเรียกเมธอดตามจำนวนตัวอักษรในสตริงทั้งหมด เช่น

- สตริงยาว 10 ตัวอักษร จะเรียกประมาณ 11 ครั้ง (รวม Base Case)
- สตริงยาว 100 ตัวอักษร จะเรียกประมาณ 101 ครั้ง
- สตริงยาว n ตัวอักษร จะเรียกประมาณ n + 1 ครั้ง

## 4. ความเสี่ยงของ StackOverflowError

Recursive มีโอกาสเกิด `StackOverflowError` หากสตริงมีขนาดใหญ่มาก เพราะทุกครั้งที่เรียกเมธอดจะใช้พื้นที่บน Call Stack เพิ่มขึ้น

ส่วน Iterative ใช้ลูปในการทำงาน จึงไม่มีปัญหาเรื่อง Stack Overflow และเหมาะกับข้อมูลขนาดใหญ่

## 5. ขนาดข้อมูลที่เหมาะสมสำหรับแต่ละวิธี

- **Recursive Counting** เหมาะกับสตริงที่มีขนาดเล็กถึงปานกลาง เพราะโค้ดอ่านง่ายและเหมาะสำหรับศึกษาหลักการ Recursion
- **Iterative Counting** เหมาะกับสตริงทุกขนาด โดยเฉพาะข้อมูลขนาดใหญ่ เนื่องจากใช้หน่วยความจำน้อยกว่าและไม่มีความเสี่ยงในการเกิด StackOverflowError
